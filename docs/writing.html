WRITING ASSISTANT / AGENT SKILL + OFFLINE CHECKS

Write, check, review.
Then revise.

The writing assistant is a paper-writing skill that you run inside an agent you already use, such as Claude Code or Codex. It instructs your agent to draft and revise one section at a time against your own evidence and to mark missing facts instead of inventing them. The draft then goes to offline checks and independent reviewer packets.

WHAT IT IS — AND IS NOT

No AI service runs on this site. Your own agent does the writing; the toolkit gives it rules, references and offline checks. This website does not read, write or review your manuscript.

01 / WHAT YOU GET

Three parts.
No hidden service.

02 / HOW THE WRITING ASSISTANT WORKS

Five steps.
One evidence trail.

Commands run from the repository root with Python 3.10+. my-paper/ stands for your own folder. If you installed only the skill, replace toolkit/paper-writing with your skill folder, for example ~/.claude/skills/paper-writing.

  1. 01

    Record what the paper claims.

    Copy the project template next to your manuscript. Fill in the thesis, audience and venue; terminology with allowed and disallowed variants; locked facts (headline numbers and the sections that state them); sources with locators and excerpts; claims marked supported, pending or unsupported; and sections whose headings match the manuscript exactly, with word limits and dependencies. Your agent can draft this file with the skill, but you approve the claim statuses.

    FILESproject-template.json ↗Fictional worked example ↗Context schema ↗

    ↳A source ID or a “supported” status is your declaration. Nothing checks that the source exists or supports the claim. An invalid context stops the first audit with exit code 2.

    REPOSITORY ROOT
    mkdir -p my-paper
cp toolkit/paper-writing/assets/project-template.json my-paper/project.json
  2. 02

    Draft or revise one section with your agent.

    With the skill installed, ask for one section at a time. The skill sends the agent to its section-craft, clarity, concept-consistency and evidence-review references. The agent returns the revised text plus notes on evidence it could not verify. Missing facts become [UNRESOLVED: …] or [CITATION NEEDED] markers, which the audit then flags.

    FILESSKILL.md ↗section-craft.md ↗clarity-and-consistency.md ↗concept-consistency.md ↗evidence-review.md ↗writing-support-guide.md ↗

    ↳Six ready-made requests are in the prompt section.

    ASK IN CLAUDE CODE OR CODEX
    Use the paper-writing skill to revise the Introduction of my-paper/manuscript.md. The project context is my-paper/project.json. Do not invent results, methods or citations; mark each gap [UNRESOLVED: what is missing] and list the evidence you could not verify.
  3. 03

    Run the mechanical audit.

    Fix every error: a missing section, an exceeded word limit, prohibited wording, an unregistered citation, or a locked number that does not match. Inspect each warning in context: a disallowed variant, a placeholder, an undefined acronym, or a fact with no nearby number. Exit code 0 means no errors (warnings are possible), 1 means errors, and 2 means invalid input. Build a section packet when you want focused agent work on one section.

    FILESpaper_harness.py ↗harness-guide.md ↗Fictional test manuscript ↗

    ↳A pass covers mechanical checks only. The output’s manual_review_needed notices list what still needs a reader.

    REPOSITORY ROOT
    # Mechanical checks; findings in the text carry line and column
python toolkit/paper-writing/scripts/paper_harness.py audit my-paper/manuscript.md --context my-paper/project.json --out my-paper/audit.json
# Optional: one section with its dependencies and evidence
python toolkit/paper-writing/scripts/paper_harness.py packet my-paper/manuscript.md --context my-paper/project.json --section results --max-chars 12000 --out my-paper/results-packet.json
  4. 04

    Hand out reviewer packets, blind reader first.

    plan writes ten isolated role packets: argument, abstract and introduction, methods, references, evidence, terminology, readability, figures, limitations and venue. Give review-plan.packets/readability.json, and nothing else, to a fresh agent session. The reader saves a teach-back of the question, approach, evidence, conditions and unclear passages before it opens comparison-context.json. Give the other nine packets to separate sessions, then merge their JSON reports. Stale hashes, missing roles, or a pass with open findings stop completion.

    FILESreview-protocol.md ↗review-roles.json ↗

    ↳The harness dispatches no agents and calls no model. Ten packets are ten tasks, not ten completed reviews. Record which agents actually ran and what each one could see.

    REPOSITORY ROOT
    python toolkit/paper-writing/scripts/paper_harness.py plan my-paper/manuscript.md --context my-paper/project.json --out my-paper/review-plan.json
# After the reviewers return their reports (in PowerShell, list each file)
python toolkit/paper-writing/scripts/paper_harness.py merge my-paper/review-plan.json my-paper/reviews/*.json --out my-paper/merged.json
  5. 05

    Score if you need a number, then revise.

    Only when a score is wanted: record each criterion’s rating, confidence and evidence in the assessment template, or export it from the workbench, then score it. Track findings in the revision ledger. Fix blockers first, then ambiguity, then prose. After editing, rerun the audit and generate a new plan; the new hashes invalidate old reviews.

    FILESLocal scoring workbench ↗Assessment template ↗Revision ledger ↗aggressive-review.md ↗

    ↳A score summarizes recorded ratings. It is not approval or an acceptance estimate, and its thresholds have no real-manuscript calibration.

    REPOSITORY ROOT
    python toolkit/paper-writing/scripts/score_evaluation.py my-paper/assessment.json --rubric toolkit/paper-writing/assets/manuscript-rubric.json --strictness aggressive --out my-paper/score.json --markdown my-paper/score.md
03 / INSTALL THE SKILL FOR YOUR AGENT

Install once.
Ask in plain words.

The skill is a folder of instructions, references and Python scripts. Your agent reads it; nothing runs as a service. The harness and scorer need Python 3.10+ and nothing from pip; the optional corpus collectors need extra packages and network access, and run only when you call them.

Download the toolkit ↓Clone from GitHub ↗
  1. 01
    Get the skill folder.

    Clone the repository or unzip the toolkit download. The folder is toolkit/paper-writing in a clone and paper-review-lab/paper-writing in the zip.

  2. 02
    Copy the whole folder.

    SKILL.md links to its references/, assets/ and scripts/ folders, so copy all of it. Claude Code: ~/.claude/skills/ for all projects, or .claude/skills/ inside one project. Codex: ~/.agents/skills/, or .agents/skills/ inside one repository.

  3. 03
    Upgrading? Delete the old copy first.

    Remove the existing paper-writing folder before copying, so stale files from an older version do not remain.

  4. 04
    Check the install.

    Start a new agent session and ask it to list its available skills; paper-writing should appear. Run the harness --help from the installed folder.

  5. 05
    Ask for the work.

    In Claude Code: “Use the paper-writing skill to …”. In Codex: “$paper-writing …”.

01 · GET THE FOLDER
git clone https://github.com/Optimizer077/paper-review-lab.git
cd paper-review-lab
02 · CLAUDE CODE / MACOS · LINUX
# Upgrading? Delete ~/.claude/skills/paper-writing first.
mkdir -p ~/.claude/skills
cp -R toolkit/paper-writing ~/.claude/skills/
python ~/.claude/skills/paper-writing/scripts/paper_harness.py --help
02 · CODEX / MACOS · LINUX
# Upgrading? Delete ~/.agents/skills/paper-writing first.
mkdir -p ~/.agents/skills
cp -R toolkit/paper-writing ~/.agents/skills/
python ~/.agents/skills/paper-writing/scripts/paper_harness.py --help
02 · WINDOWS / POWERSHELL
# Claude Code. For Codex, write .agents in place of .claude.
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item -Recurse toolkit\paper-writing "$HOME\.claude\skills\"
python "$HOME\.claude\skills\paper-writing\scripts\paper_harness.py" --help

Use python3 where python is not on your PATH. The fictional examples in toolkit/examples and the citation library in toolkit/research sit outside the skill folder; writing does not depend on them. Skill locations can change between agent versions, so check your agent’s skill documentation if the skill does not appear.

04 / COPY-PASTE PROMPTS

Ask for the work.
Keep the numbers yours.

Paste a prompt into your agent after installing the skill and replace the highlighted slots. Replace <skill-dir> with your installed folder. Each prompt asks the agent to keep your numbers, mark gaps and say what it could not check. Select the text to copy it, or use its Copy button.

PROMPT 01

Revise an abstract against the evidence

Use when the abstract no longer matches the results.

Use the paper-writing skill. Revise the abstract of my-paper/manuscript.md for [VENUE, YEAR, TRACK]. The project context is my-paper/project.json.

Keep every number, comparator, metric direction, unit, denominator and uncertainty exactly as reported in the Results section and in locked_facts. Do not add results, citations, datasets or claims that are not already in the manuscript. If a needed fact is missing, write [UNRESOLVED: what is missing] instead of filling it in.

Return: (1) the revised abstract; (2) a table mapping each sentence to its supporting manuscript location or claim ID; (3) every statement you weakened or removed, and why.

Then run `python <skill-dir>/scripts/paper_harness.py audit my-paper/manuscript.md --context my-paper/project.json` and report its findings as printed. Do not describe a clean audit as proof that the abstract is correct.
PROMPT 02

Tighten an introduction without losing its logic

Use when the introduction is over length or loses the thread.

Use the paper-writing skill and its section-craft reference. Tighten the Introduction of my-paper/manuscript.md to at most [N] words (the max_words in my-paper/project.json).

First, list a one-sentence job for each current paragraph and the dependency it carries. Keep the logic problem → relevant knowns → specific justified gap → approach → bounded contribution, but do not force a fixed number of paragraphs.

Do not write "first", "novel" or "no prior work" unless a comparison in the manuscript supports it; otherwise state the concrete difference from the closest cited work. Do not invent citations; mark missing ones [CITATION NEEDED].

Return the revised text, the paragraph-job list, and a list of what you cut and which dependency each cut carried.
PROMPT 03

Terminology and acronym consistency pass

Use when one idea has several names, or acronyms go undefined.

Use the paper-writing skill (clarity-and-consistency and concept-consistency references). Read my-paper/manuscript.md in full and build a terminology ledger with these columns: concept ID, canonical term, operational definition, permitted aliases, disallowed variants, and first definition in the abstract and in the body.

Flag (a) one label used for two different objects, (b) two labels for the same object, (c) acronyms not expanded at first use in the abstract and again in the body, and (d) symbols or units that change meaning.

Do not edit the manuscript yet. Propose additions to the terminology entries (including their disallowed_variants) and to acronym_allowlist in my-paper/project.json for my approval.

Then run the harness audit and, for each terminology_inconsistent and acronym_definition warning, give the line and say whether it is a real problem after reading the context.
PROMPT 04

Claim-to-evidence check

Use before submission, or when a reviewer questions a claim.

Use the paper-writing skill and its evidence-review reference. For each central claim in the title, abstract, contribution list and conclusion of my-paper/manuscript.md, build a table with these columns: exact claim text and location; claim type (observation, mechanism, formal guarantee, association, causal); comparator; metric and direction; denominator or independent unit; uncertainty as reported; supporting table, figure or theorem; status (supported by a passage I inspected / needs evidence / overstated / contradicted).

Cite only evidence you actually read in the manuscript or the files I supplied; write "not inspected" otherwise. List blockers first. For overstated claims, propose the narrowest wording the evidence supports. Do not change numbers and do not propose analyses as if they had been done.
PROMPT 05

Blind-reader teach-back with the harness packets

Use to learn what a fresh reader actually understands.

Run `python <skill-dir>/scripts/paper_harness.py plan my-paper/manuscript.md --context my-paper/project.json --out my-paper/review-plan.json`.

Start a separate sub-agent and give it only my-paper/review-plan.packets/readability.json. It must write, in its own words, the question and why it matters, the approach, the evidence and main finding, the conditions under which the conclusion holds, and the passages it found unclear, each with a manuscript locator. It must save this to my-paper/reviews/teachback.md before opening comparison-context.json.

Then compare the teach-back with the claim ledger and fill in the report_template as my-paper/reviews/readability.json. Tell me exactly which agents ran and what each one could see. If you cannot run an isolated sub-agent, say so and stop; do not write the teach-back yourself after reading the context.
PROMPT 06

Point-by-point reviewer response

Use when answering reviewers after a revision.

Use the paper-writing skill. Inputs: reviewer comments in my-paper/reviewer-comments.txt, the revised manuscript my-paper/manuscript.md, and my notes on what changed in my-paper/changes.md.

Draft a point-by-point response. Split multi-part comments. For each point give a direct answer, then either the actual change with its verified location in the revised file or a reasoned disagreement. Label each item: clarified / new analysis completed / proposed, not done / disagree.

Do not claim any experiment, number, page, line or change that is not in the revised file or my notes; mark gaps [UNRESOLVED]. Finally, check that the abstract and conclusion still match the revised results, and list any mismatch.

05 / WHAT IT DOES — AND DOES NOT DO

Useful checks.
Honest limits.

The skill and harness make the reasoning easier to inspect. They do not replace the person or agent who reads the paper, the sources and the data.

What it does

  • +

    Drafts and revises one section at a time inside your agent, following the section-craft, clarity, concept and evidence references.

  • +

    Instructs your agent to keep comparators, denominators, metric direction, units, negation and uncertainty as reported, and to mark missing facts instead of filling them in.

  • +

    Reconciles the title, abstract, introduction, contributions, results, captions and conclusion after each substantive change.

  • +

    Audits mechanically for missing sections, word limits, prohibited wording, unregistered citations, locked-number mismatches, disallowed variants, placeholders and undefined acronyms, with a line and column for each finding located in the text.

  • +

    Prepares ten isolated reviewer packets, blind reader first, and rejects returned reports with stale hashes, missing roles or a pass with open findings.

  • +

    Scores ratings that a person or agent recorded with evidence, and reports raw and capped scores, coverage and blockers separately.

What it does not do

  • ×

    Run on this website. There is no upload, model call or server; this site does not read, write or review your manuscript. Your agent does send the text it reads to the model service it uses, under that service’s terms. Do not give it a confidential submission you were assigned to review unless the venue’s policy allows it (venue notes ↗).

  • ×

    Guarantee that your agent will not invent results, methods, datasets, citations, ethics approvals or completed revisions. The skill tells it not to, but the audit only flags leftover markers, unregistered citation keys and mismatches against locked numbers. Check every number and reference yourself.

  • ×

    Verify that a citation exists, that a source supports a claim, that a number refers to the right cohort, or that the paper is readable.

  • ×

    Dispatch agents or prove that the blind reading order was followed. Ten generated packets are not ten completed reviews.

  • ×

    Produce ratings by itself, predict acceptance, or certify scientific quality or submission readiness. Its thresholds are uncalibrated editorial conventions.

  • ×

    Disguise AI-assisted text or replace a venue’s AI-use rules. The venue notes are a dated snapshot; check the current instructions for your cycle and track.

↳

A passing audit is a prompt for inspection. It does not establish that a citation exists, a result is correct, or the paper is readable. The bundled manuscript, context and demo assessment are fictional fixtures for trying the tools, not research evidence.
